# План работ

﻿Этап 0. Фундамент и контракты
* Репозиторий и окружение
   * Инструменты: Git, Docker Compose, Makefile, .env
   * Реализовать: структура /api /connectors /worker /simulator /mock-1c /web /deploy; make up поднимает PG+PostGIS, ClickHouse, Redis, Mosquitto с healthchecks; make seed, make reset
* Контракт события
   * Инструменты: Pydantic v2, JSON Schema
   * Реализовать: модель Event{event_id, schema_v, sensor_id, type, ts, received_at, payload, geo?, zone_id?}; payload-схемы по типам датчиков; общий пакет common/, который используют все процессы
* API-контракт для фронта
   * Инструменты: FastAPI (OpenAPI), openapi-typescript, MSW или Prism для моков
   * Реализовать: описанные эндпоинты со схемами ответов и формат WS-сообщений; фронт стартует на моках, не дожидаясь бэка
* План предприятия
   * Инструменты: GeoJSON, geojson.io или QGIS
   * Реализовать: локальная СК в метрах; здания, этажи, помещения, дороги, КПП, геозоны, точки датчиков; файл seed/layout.geojson
Этап 1. Хранилища
* Postgres
   * Инструменты: SQLAlchemy 2, Alembic, GeoAlchemy2, asyncpg
   * Реализовать: таблицы users, roles, sensor_types, sensors (is_mobile), thresholds (version), buildings, zones (geometry), layouts (version), alert_rules (version), alerts, whitelist, schedules, api_keys, vehicles; первая миграция
* ClickHouse
   * Инструменты: clickhouse-connect, SQL-миграции
   * Реализовать: telemetry (ReplacingMergeTree по event_id, партиция по дню, TTL 30д), MV telemetry_1m (min/avg/max/count, TTL 1 год), alerts_log
* Redis
   * Инструменты: Redis 7, redis-py asyncio
   * Реализовать: соглашение по ключам: stream:events, stream:dlq, stream:alerts, live:sensor:{id}, zone:{id}:people, alert:open:{rule}:{sensor}, ZSET last_seen, каналы pub/sub live:{building}:{layer}
* Сиды
   * Инструменты: Python-скрипт, Faker
   * Реализовать: здания и зоны из GeoJSON, 50–200 датчиков, машины, пропуска (whitelist), расписания, правила алертов, пользователи по ролям
Этап 2. Приём данных (коннекторы)
* Сервис connectors
   * Инструменты: FastAPI, aiomqtt + Mosquitto, slowapi
   * Реализовать: POST /ingest/{type} и MQTT-топики sensors/{type}/{id}; авторизация по API-ключу; rate limit; валидация по схеме типа; XADD в stream:events; невалидное в stream:dlq
* Адаптеры по типам
   * Инструменты: Pydantic, паттерн «адаптер»
   * Реализовать: маппинг вендорского payload → контракт для камеры (гос. номер), СКУД (пропуск, направление), ГЛОНАСС (координаты, скорость, топливо), движения, климата (температура, влажность); добавление типа = один класс
* Симулятор
   * Инструменты: asyncio, httpx, aiomqtt, Shapely (интерполяция по маршрутам), YAML-сценарии
   * Реализовать: машины ездят по дорогам плана, турникеты по графику смен, климат с шумом; сценарии «поломка», «пропуск вне базы», «нерабочее время», «перегрев склада», «датчик offline»; ручка POST /scenario/{name} для запуска на демо; трафик идёт только через connectors
Этап 3. Обработка потока (worker)
* Запись в ClickHouse
   * Инструменты: XREADGROUP, clickhouse-connect
   * Реализовать: батч по 1–2 с или N событий; XACK после успешной вставки; ретраи; при сбое события остаются в стриме
* Обогащение
   * Инструменты: Shapely STRtree
   * Реализовать: zone_id по point-in-polygon; скорость и направление для подвижных; вход/выход из геозоны как производное событие
* Live-состояние
   * Инструменты: Redis hash, ZSET, pub/sub
   * Реализовать: последняя позиция и статус датчика, людей в зоне по СКУД, last_seen; публикация изменений в каналы по зданию и слою
* Движок алертов
   * Инструменты: Python, Redis (состояние), Postgres (история)
   * Реализовать: правила min/max/critical, геозона, расписание, whitelist, скорость; состояния open → ack → resolved; дедуп и гистерезис; эскалация по таймеру; фоновая проверка offline по last_seen; запись rule_id + version; публикация в stream:alerts и WS
Этап 4. API (монолит)
* Auth
   * Инструменты: PyJWT, argon2-cffi
   * Реализовать: login, refresh, роли диспетчер/охрана/админ, зависимость проверки прав; маскирование ФИО для роли без прав
* Реестр и разметка
   * Инструменты: FastAPI, SQLAlchemy, GeoAlchemy2
   * Реализовать: CRUD датчиков, типов, порогов, зон; GET /objects (вся статика одним ответом); POST /layout с проверкой версии (409 при конфликте)
* Bulk-загрузка датчиков
   * Инструменты: csv/pandas, Pydantic
   * Реализовать: CSV/JSON, ?dry_run=true возвращает ошибки построчно; применение в транзакции
* Live
   * Инструменты: FastAPI WebSocket, Redis pub/sub
   * Реализовать: GET /state/live (снимок), WS /ws/live с подпиской по зданию, слою, типу
* История и KPI
   * Инструменты: ClickHouse SQL
   * Реализовать: /sensors/{id}/history, /vehicles/{id}/route, /replay?from&to, /kpi (простои, пробег, проходы через КПП, топ алертов), /heatmap
* Алерты
   * Реализовать: GET /alerts с фильтрами, POST /alerts/{id}/ack, комментарий, resolve
Этап 5. Фронтенд
* Каркас
   * Инструменты: Vue 3, TypeScript, Vite, Pinia, Vue Router, openapi-typescript
   * Реализовать: авторизация, роутинг по ролям, типизированный API-клиент, WS-стор с переподключением
* Карта
   * Инструменты: Leaflet CRS.Simple или MapLibre
   * Реализовать: план предприятия, слои (здания, датчики, техника, люди по зонам, алерты), переключение этажей, плавная анимация движения
* Алерты
   * Реализовать: лента с критичностью, подсветка на карте, ack и комментарий, звук для critical
* Карточка датчика
   * Инструменты: ECharts
   * Реализовать: текущее значение, график истории с порогами, статус online/offline
* KPI-дашборд
   * Инструменты: ECharts
   * Реализовать: виджеты KPI, фильтр периода
* Реестр датчиков
   * Реализовать: таблица, форма, загрузка CSV с предпросмотром ошибок
* Replay и heatmap
   * Инструменты: deck.gl (TripsLayer, HeatmapLayer)
   * Реализовать: таймлайн с прокруткой и скоростью воспроизведения, тепловая карта загруженности
Этап 6. Интеграции
* ВК-бот
   * Инструменты: vkbottle или vk_api
   * Реализовать: consumer stream:alerts, отправка по подписке и критичности, кнопка «подтвердить»
* Мок 1С-ЭПД
   * Инструменты: FastAPI, seed JSON
   * Реализовать: поиск по гос. номеру → рейс → статусы ЭТрН/ЭПЛ/ЭЭЗ; worker при въезде в геозону КПП обогащает событие; на фронте бейдж статуса документа
* Страница коннекторов
   * Реализовать: каталог типов, пример payload, curl и MQTT-пример, выдача API-ключа
Этап 7. «Вау»-фичи
* Редактор «Sims»
   * Инструменты: Konva (vue-konva)
   * Реализовать: рисование помещений, drag&drop датчиков из палитры, радиус покрытия, задание номиналов, сохранение layout с версией, новые датчики сразу видны в симуляторе
* Предиктив
   * Инструменты: pandas/numpy, EWMA, z-score
   * Реализовать: оценка износа и аномалий по telemetry_1m, /predict/{sensor_id}, прогноз «до обслуживания»
* Нагрузка и наблюдаемость
   * Инструменты: Locust или async-генератор, Prometheus, Grafana, prometheus-fastapi-instrumentator
   * Реализовать: метрики events/s, lag стрима, время вставки; реальный замер пропускной способности для слайда
Этап 8. Демо
* Сценарий показа
   * Инструменты: скрипт поверх POST /scenario
   * Реализовать: 5–7 минут: карта в движении → поломка машины → алерт в UI и ВК → въезд с ЭТрН → добавление датчика в редакторе → KPI и replay
* Стабилизация
   * Реализовать: make reset && make seed && make demo с чистого состояния; прогон 2–3 раза; запасная видеозапись демо
* Презентация
   * Реализовать: схема архитектуры (три уровня задания), стек, цифры нагрузки, roadmap (выделение модулей в сервисы, Kafka, реальные коннекторы)
